### Layering violations found (not in any doc)

1. **Data layer → UI root**: `src/data/utils/plugins.ts` and `src/data/models/worker/worker.utils.ts` import `workerPlugins` from `@/App`. Data depends on the React root module — this is the kind of edge an architecture unit test should lock down.
2. **Data util → Zustand store**: `src/data/utils/canvas.ts` imports `useFSHandleStore`.
3. **Misleading name**: `src/hooks/data/convertedFiles/useRepository.tsx` is a *GitHub repo* import hook (Octokit), not a data repository.
4. `src/state/states.md` documents `manifests`/`selection` reducers that no longer exist — doc drift inside `src/`.
5. `public/doc/architecture.md` Flux 3 cites plugins `tesseract.ts`, `surya.ts` — dead code living in `workers/old/`, loaded by nothing.

## 6. Test gaps, and how to get to the three goals

### Unit tests (vitest — tooling already present)
Untested core, by risk order:
1. **Repositories** (`src/data/repositories/**`) — never executed, only `vi.mock`'d. `fake-indexeddb` is already installed and sanctioned by plan-table-seam Phase 1; the harness (`createTestDb()`) is the highest-value missing file in the repo.
2. **Status law** — 4 divergent copies; write the Phase-0 characterisation tests from `plan-worker-status-law.md` *before* any refactor.
3. **Sagas** (`sagas/workers.ts` ~420 lines) — `redux-saga` effects are unit-testable with `redux-saga-test-suite` or by driving the `effect` iterator; this also unblocks the documented saga retirement.
4. Worker plugins, `useJobRealtime`, `excel.utils.ts`, `OpenAICompatibleClient` (~500 lines untested).
5. Playwright: still absent; doc 06 (priority 3) plans 2–4 critical paths.

### Semgrep
Not installed anywhere. Setup path: `pipx install semgrep`, add a `semgrep/` rules dir (registry rules: `p/typescript`, `p/react`, `p/react-security` + custom rules codifying house style — e.g. ban `@ts-expect-error` growth, ban importing `@/App` from `src/data/`), and wire `semgrep scan --config semgrep/ src/` into the same CI job as lint. 8 existing `@ts-expect-error` suppressions (`ban-ts-comment`) are the current baseline to ratchet.

### Architectural unit tests
Nothing enforces layering today — and there are already violations (§2). Two complementary options:
- **eslint-plugin-boundaries** (preferred: same process as lint): element pattern on `src/*` top dirs, rules like `data` may not import `components`/`App`, `components` may not import `state/sagas`, etc. Fails on the two known violations immediately.
- **Vitest + madge** graph test: an assertion-style test (`expect(madge(...)).toHaveDependency(...)`) per allowed edge, plus the *grep gate* already specified in plan-worker-status-law exit criteria (`case WorkerStatus.` outside the law module ⇒ fail). This is CI-free and matches the "unit test the architecture" ask literally.

### CI (blocks all three)
Doc 06 §4 promises a PR gate of lint + test + build; it does not exist. Add one workflow running `tsc -b`, `eslint .`, `prettier --check`, `vitest run` (+ semgrep once configured), and gate gh-pages on it.
